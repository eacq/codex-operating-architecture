# Global Codex Project Lifecycle

- Artifact-root rule: new project files, reports, runtime evidence, caches,
  backups, and generated outputs must be created under `F:\codex` or a
  descendant by default. Do not create new task artifacts on another drive;
  an explicitly user-scoped external source may be read in place, but derived
  outputs must return to `F:\codex`. System-owned memory and existing global
  discovery interfaces remain managed exceptions and must not be copied into
  the project.
- At the start of work in any project, invoke `$codex-self-evolution` as the lifecycle controller before selecting narrower skills.
- During every Codex project entry, start or resume the one Global Experience Agent by default unless the user explicitly authorizes skipping it for that turn. Run project-entry checks, load `config/agent-system.json`, `agent/agent-filesystem.json`, and `config/global-experience-agent-registry.json`, and use `agent/40-runtime/Invoke-GlobalExperienceAgent.ps1`: `Run StartWork` creates durable work and retrieves records; `Resume` reconstructs work, records, next actions, histories, and child state; `Continue` permits another authorized caller/model host to act from an idle save point. A skip authorization only omits the Agent durable session; it never skips `$codex-self-evolution`, Codebase Memory `F-codex` startup/indexing when applicable, safety/privacy/rollback/validation gates, owner routing, or permission checks. `RouteOwner` resolves one of 23 specialist Agents without executing gated side effects; delegate/complete/join/cancel operations own bounded child-Agent lifecycles. Specialist and concept Agents never replace owner tool gates or become parallel global-system entrypoints.
- During every Codex project entry, run `$ARCHITECTURE_ROOT\scripts\Start-CodebaseMemoryGraphUi.ps1` for `F:\codex` on `127.0.0.1:9749`; it blocks until the UI service itself has indexed the Global Experience Agent as `F-codex`. Before treating `codebase-memory-mcp` as unavailable, query the current task's deferred/namespaced callable capability registry. When callable, always refresh the global evidence graph with `index_repository(repo_path="F:\\codex", mode="fast", name="F-codex")`; refresh a different current source repository only when source-structure evidence is relevant to the task, and do not leave external/reference indexes in the global cache when the single-project `F-codex` validation gate must pass. Treat `F-codex` as the Global Experience Agent's structural index; do not create aliases. Only after the registry check proves the MCP unavailable, or when the task has no relevant source-structure work, may normal local evidence proceed without MCP graph citation.
- Check `<project-root>/.codex/project/state.json`. If it is missing, invoke `$codex-project-optimization` and initialize requirements, workflows, experience, retrospectives, and lifecycle state before substantial project changes.
- Read project requirements, workflows, and relevant verified experience before planning or implementation. Project facts remain in that project.
- When the user reports an error, failure, missing behavior, or wrong result, invoke `$codex-error-feedback`: retain the redacted user wording, create a project error report, attempt only a safe targeted repair, verify it, and promote only verified lessons.
- When Codex, the Global Experience Agent, or a specialist/concept/child Agent reports a known stream, TLS, connection, or request-timeout failure before completion, activate `config/agent-transport-recovery-policy.json` through `agent/40-runtime/Get-AgentTransportRecoverySignal.ps1`: stop automatic retry, persist durable session and pending writes, return typed `restart-required`, and immediately tell the user to restart Codex or the affected host. After restart, use `Resume` before `Continue`; never leave the task or child Agent waiting indefinitely.
- A native Codex transport failure may prevent the model from emitting a later message. The host-facing recovery contract must surface the restart prompt at the error boundary, while the Agent runtime state remains the durable recovery source.
- When a Codex app snapshot is available, call `agent/40-runtime/Get-AgentHostRecoverySignal.ps1` with the `list_threads`/`wait_threads` snapshot. A stale active `inProgress` turn with no assistant/tool marker, or with a stale `inProgress` tool marker, becomes `host-stall-suspected`; persist the marker and prompt for restart, but never force-kill the task. This check is the host-level bridge when no error string reaches the Agent runtime.
- After a Git initialization, commit, merge, rebase, tag, release, or complete verified iteration, invoke `$codex-experience-capture`, reconcile project lifecycle files, and process pending Git events.
- Before closing any global experience-system task, align the agent exit: record tool results or error feedback, run the narrowest proving check, accept or reject a save point, update lifecycle/candidate state, generate the current candidate report after complete global iterations, route Git/release/install/credential/publication/top-owner actions through their gates, and report residual risk plus the next authority boundary.
- Promote only verified, non-duplicate, cross-project lessons into the canonical architecture at `$ARCHITECTURE_ROOT`; keep candidates and project-specific knowledge in the project.
- Global architecture skills under `$CODEX_HOME\skills` are discovery interfaces to `$ARCHITECTURE_ROOT\skills`. Edit, validate, version, and roll back them only through the canonical repository.
- Scale the lifecycle work to the task. A read-only or trivial request may only need the entry check; do not create unrelated project churn.
