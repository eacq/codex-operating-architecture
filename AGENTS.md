## Codex Project Lifecycle

- At every project entry, invoke `$codex-self-evolution` to route the task and check lifecycle state.
- At every Codex project entry, start or resume the one Global Experience Agent by default unless the user explicitly authorizes skipping it for that turn: load `config/agent-system.json`, `agent/agent-filesystem.json`, and `config/global-experience-agent-registry.json`, then use `agent/40-runtime/Invoke-GlobalExperienceAgent.ps1`. `Run StartWork` creates durable work and retrieves records; `Continue` permits another authorized caller/model host to act from an idle save point; `Resume` reconstructs work, records, next actions, histories, memory, and child state. A skip authorization only omits the Agent durable session; it never skips lifecycle entry, Codebase Memory `F-codex` startup/indexing when applicable, safety/privacy/rollback/validation gates, owner routing, or permission checks. `RouteOwner` resolves one of 23 specialist Agents without executing gated side effects; delegate/complete/join/cancel operations own bounded child-Agent lifecycles. Specialist and concept Agents never replace owner tool gates or become parallel global-system entrypoints.
- When `codebase-memory-mcp` tools are exposed, run the MCP startup preflight through the Agent entry path: refresh `F:\codex` as the canonical `F-codex` graph before broad file reading or architecture claims; index another source repository only when source-structure evidence is relevant, and do not leave external/reference indexes in the global cache when the single-project `F-codex` gate must pass.
- On first use, when `.codex/project/state.json` is absent, invoke `$codex-project-optimization` and initialize the project lifecycle before substantial work.
- Before planning or implementation, read `.codex/project/REQUIREMENTS.md`, `WORKFLOWS.md`, and relevant `EXPERIENCE.md` entries.
- After Git initialization, commit, merge, rebase, tag, release, or a complete verified iteration, invoke `$codex-git-operations` and `$codex-experience-capture`.
- Before closing global experience-system work, align the exit through the agent save point: tool results or error feedback, narrowest proving check, lifecycle/candidate-state update, candidate report when applicable, gated Git/release/install/credential/publication/top-owner routing, residual risk, and next authority boundary.
- When Codex, the Global Experience Agent, or a specialist/concept/child Agent reports a known stream, TLS, connection, or request-timeout failure before completion, activate `config/agent-transport-recovery-policy.json` through `agent/40-runtime/Get-AgentTransportRecoverySignal.ps1`: stop automatic retry, persist durable session and pending writes, return typed `restart-required`, and immediately tell the user to restart Codex or the affected host. After restart, use `Resume` before `Continue`; never leave the task or child Agent waiting indefinitely.
- A native Codex transport failure may prevent the model from emitting a later message. The host-facing recovery contract must surface the restart prompt at the error boundary, while the Agent runtime state remains the durable recovery source.
- When a Codex app snapshot is available, call `agent/40-runtime/Get-AgentHostRecoverySignal.ps1` with the `list_threads`/`wait_threads` snapshot. A stale active `inProgress` turn with no assistant/tool marker, or with a stale `inProgress` tool marker, becomes `host-stall-suspected`; persist the marker and prompt for restart, but never force-kill the task. This check is the host-level bridge when no error string reaches the Agent runtime.
- Process `.codex/project/pending-events.jsonl`, then synchronize requirements, workflows, project experience, retrospectives, and lifecycle state.
- Keep project-specific knowledge in this repository. Promote only verified cross-project rules to the global Codex skills.
- Preserve user content outside this managed block and never store credentials or raw private session content.
