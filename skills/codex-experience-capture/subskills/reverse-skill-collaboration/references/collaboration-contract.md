# Local collaboration mapping

| reverse-skill concept | Local owner or artifact | Adaptation rule |
|---|---|---|
| `scope.md` with auth, in/out scope and network profile | Global Experience Agent work record, project requirements, privacy/authority gates | Express the same boundary for any multi-Agent task; it does not grant target authorization. |
| `role-map.md` | Root owner routing and specialist Agent registry | One owner remains authoritative; specialist Agents return bounded results. |
| Evidence→Finding→Path | Evidence records, validation output, decision lineage, LoopX trajectory | Every promoted lesson or handoff cites an observable source. |
| `timeline.md` and `workitems.md` | durable work, todo/lease, turn receipts, project lifecycle | Append state transitions; preserve revision and rollback evidence. |
| `skill-supply-chain.md` | codex-tool-installation, skill-portability, architecture iteration | Review source and install only the smallest owner-scoped adapter. |
| `case-guard.ps1` | existing authorization, privacy, rollback, publication and validation gates | Use as a pattern, never as a bypass or a replacement for local gates. |

## Negative boundaries

- A request containing “reverse skill” alone does not route to a target-facing security skill.
- A specialist cannot self-authorize external installation, credential use, network access, publication, destructive changes, or a second global controller.
- A plausible narrative without evidence remains a candidate, not a verified lesson.
- A timeout or transport failure ends the active attempt at a durable recovery boundary; it is not permission for unbounded retries.
