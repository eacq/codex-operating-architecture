# Global Experience Agent Architecture PNG Provenance

## English

- Asset: `global-experience-agent-architecture.png`.
- Purpose: explain one durable global experience root Agent, its ten-zone physical Agent filesystem, four permission interfaces, default-deny structural boundary, typed exits, caller/model-neutral continuation contract, five concept Agents, all 23 specialist Agents, executable child-Agent lifecycle, and the exact module-to-capability correspondence.
- Visual class: mapping-driven deterministic architecture infographic, regenerated from the current Agent manifest and owner registry rather than from a previous image.
- Final format: lossless PNG at 3840 x 2400. The PowerShell renderer and JSON correspondence model are the editable authoritative sources.
- Theme: warm ivory canvas, deep navy Agent loop, and distinct teal, violet, green, amber, and coral responsibility accents.
- Module correspondence: `config/agent-architecture-diagram.json` groups all 23 active owners as specialist Agents in four planes: control, evidence and experience, delivery capabilities, and platform/tool gates. Each specialist declares its primary Agent-stage anchor, concise responsibility, and durable output. `Test-AgentArchitectureDiagram.ps1` rejects missing, duplicate, extra, or stage-less owners.
- Agent registry: `config/global-experience-agent-registry.json` is the canonical identity and composition source for the one root Agent, five concept Agents, 23 specialist-Agent adapters, caller/model/host labels, cross-caller continuation, and the delegated -> completed -> joined/cancelled child lifecycle. Concept Agents compose existing owners and never create a duplicate top-level owner.
- Agent filesystem: `agent/agent-filesystem.json` defines the root, interface, Agent, resource, runtime, evidence, exit, presentation, maintenance, and local-state zones. Generated manifests point to canonical owners and are checked for deterministic drift; private runtime state stays outside the tree.
- Interface policy: `config/agent-interface-policy.json` is the executable source for the human, LLM, internal-functional-unit, and global-control interfaces. Human, LLM, and internal calls cannot directly mutate Agent structure; global-control requires current global-structure evidence and routes to `codex-architecture-iteration` through the `agent_structure` gate. All calls expose typed exits.
- Owner network: `config/agent-owner-connections.json` is the executable connection source. It binds every owner to its canonical skill, triggers, inputs, outputs, verification, optional tool gate, incoming handoffs, and outgoing handoffs. The image shows the live in/out route count and gate class for every module card; the detailed 50 handoffs remain machine-readable to avoid line clutter.
- Agent loop: start work -> retrieve durable records -> Continue or Resume under the current authorized caller/model/host -> select a concept or specialist Agent -> gated execution or bounded child delegation -> result observation -> child settlement -> accepted save point -> next authorized caller.
- Global experience loop: verified results flow through experience capture and linked knowledge, then become bounded input to the next immutable snapshot.
- Generator: `scripts/New-AgentArchitectureDiagram.ps1`.
- Validation: `scripts/Test-AgentArchitectureDiagram.ps1`, Agent topology and harness tests, original-resolution inspection, and complete transactional global iteration.
- Privacy boundary: the mapping and image contain no local paths, credentials, raw private sessions, prompts, completions, tool payloads, shell output, request headers, repository secrets, account names, or user data.
- Regenerate when: the physical Agent filesystem, root or concept Agent registry, interface/permission/exit policy, active specialist owner registry, dynamic child lifecycle, Agent runtime stages, owner responsibility boundary, durable output, tool-gate routing, caller/model continuation contract, session/save-point contract, or global experience feedback loop changes materially.

## Chinese / 中文

- 资源：`global-experience-agent-architecture.png`。
- 用途：说明当前可执行全局经验 Agent，并明确展示每个 active 顶层 Owner 与一个主要 Agent 阶段、一项核心责任和一种持久产物之间的对应关系。
- 视觉类型：由当前 Agent 清单和 Owner 注册表驱动的确定性架构信息图，不以旧图为生成依据。
- 最终格式：3840 x 2400 无损 PNG；PowerShell 渲染器与 JSON 模块对应模型共同构成可编辑权威源。
- 主题：暖象牙色画布、深海军蓝 Agent 运行循环，以及青绿、紫色、绿色、琥珀色与珊瑚色责任分区。
- 模块对应：`config/agent-architecture-diagram.json` 把全部 23 个 active Owner 分成控制面、证据与经验面、交付能力面、平台与工具门禁面。每个 Owner 都声明主要 Agent 阶段、简明职责与持久产物；`Test-AgentArchitectureDiagram.ps1` 会拒绝缺失、重复、额外或无阶段映射的 Owner。
- Agent 文件系统：`agent/agent-filesystem.json` 定义十个生命周期分区；投影清单只引用规范 Owner Skill，本地私有状态保留在树外，并由漂移测试校验。
- Owner network：`config/agent-owner-connections.json` 是可执行连接权威源，把每个 Owner 绑定到规范 Skill、触发条件、输入、输出、验证、可选工具门禁、传入 handoff 和传出 handoff。图中每张模块卡显示实时 IN/OUT 路由数及门禁类别；详细的 50 条连接保留在机器可读配置中，避免连线遮挡。
- Agent 循环：任务契约 → 持久会话 → 不可变快照 → Owner 调度 → 门禁执行 → 结果观测 → 接受保存点 → 经验回流至下一回合。
- 全局经验闭环：已验证结果进入经验提炼和链接知识，再作为受边界约束的输入进入下一次不可变快照。
- 生成器：`scripts/New-AgentArchitectureDiagram.ps1`。
- 验证：运行 `scripts/Test-AgentArchitectureDiagram.ps1`、Agent 拓扑与 Harness 测试，按原始分辨率检查，并执行完整事务式全局迭代。
- 隐私边界：映射和图片不包含本机路径、凭据、原始私有会话、提示词、补全文本、工具载荷、Shell 输出、请求头、仓库秘密、账户名或用户数据。
- 重新生成条件：active Owner 注册表、Agent 运行阶段、Owner 责任边界、持久产物、工具门禁路由、会话/保存点契约或全局经验反馈闭环发生实质变化。
